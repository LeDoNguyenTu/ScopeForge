# Phase 3N SARIF Output Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add deterministic SARIF 2.1.0 output compatible with GitHub Code Scanning while preserving ScopeForge finding identity, baseline state, safe evidence, and existing CLI policy behavior.

**Architecture:** Add a focused SARIF serializer under `packages/scanner-output/sarif` that consumes only the normalized `ScanResult` contract and never reads repository files itself. Extend the existing output-format type, repository configuration parser, and CLI renderer so `--format sarif` shares the existing scan, baseline, policy, and safe-output pipeline. The serializer builds a deterministic rule table and result list, maps ScopeForge severity to SARIF levels, preserves stable fingerprints in `partialFingerprints`, maps baseline state to SARIF's supported values, and emits only already-normalized safe finding data.

**Tech Stack:** TypeScript, Vitest, SARIF 2.1.0 JSON, existing ScopeForge scanner-core, CLI, and safe-output contracts.

**Spec:** `docs/superpowers/specs/2026-08-24-phase-3-code-supply-chain-design.md`

## Global Constraints

- SARIF version is exactly `2.1.0`.
- Output must be compatible with GitHub Code Scanning's supported SARIF subset.
- Rule IDs and finding fingerprints remain stable and are not regenerated by the output adapter.
- Result ordering and rule-table ordering are deterministic and locale independent.
- Secret values, arbitrary finding metadata, source snippets, and repository configuration values must never be copied into SARIF by the adapter.
- SARIF consumes normalized finding evidence and remediation only. It does not read repository files, execute repository code, or initiate network access.
- `critical` and `high` map to SARIF `error`, `medium` maps to `warning`, and `low`/`info` map to `note`.
- ScopeForge `new` maps to SARIF `new`, `existing` maps to SARIF `unchanged`, and `none` omits SARIF `baselineState`.
- `partialFingerprints["scopeforge/v1"]` contains the existing ScopeForge finding fingerprint.
- File locations remain repository-relative and use `%SRCROOT%`; unsafe absolute/traversal locations are omitted rather than rewritten outside the repository boundary.
- Existing report-only, `--fail-on`, scanner-error, baseline, SBOM, JSON, terminal, and safe-output behavior must remain unchanged.

- [ ] **Step 3: Implement the minimal serializer**

Implement these helpers in `serialize.ts`:

```ts
export interface SerializeSarifOptions {
  toolVersion?: string;
}

export function serializeSarifResult(
  result: ScanResult,
  options: SerializeSarifOptions = {}

The serializer emits `ruleId`, `ruleIndex`, level, safe message text, physical location when safe, stable partial fingerprint, safe ScopeForge properties, and supported baseline state.
